# teleConnect 第65版更新记录与功能说明

[打开第65版原型](../versions/v65/) · 本机预览（本机预览）

本版保留第64版，不生成ZIP。更新集中在任务跳转与返回、未提交表单、编辑草稿保护，复用已有任务、运行、会话和配置页面。

## 任务表单：每一次待办单独保留

用户正在填写的审批意见、处理结果、补充信息归属于当前用户、当前运行和当前待办。打开另一任务时，不带入前一个任务的内容；通过浏览器返回、跨端查看后返回，也恢复到本任务自己的填写。

临时表单与正式处理结果不同。查看详情、离开任务或返回不会提交审批，更不会恢复旧的运行状态。只有点击实际处理按钮且通过当前权限、时限、计划及依据检查后，才处理待办。

若待办已办理、转派，或者处理权限、诊断依据与操作计划发生变化，原填写不能继续套用，界面提示重新核对。提交时仍检查处理时限、证据时效与操作计划是否有效；过期不因保留填写而获得执行许可。同一有效待办在页面内刷新或返回时保留填写；不同待办、不同用户之间隔离。原型也尝试使用当前标签页的临时存储恢复整页刷新后的填写，恢复前再次核对待办与依据版本。

填写区出现“本页已暂存，尚未提交”，表示当前浏览器临时保留，并未提交处理结果。整页刷新或关闭浏览器时，只要当前成员仍有有效暂填内容，就使用浏览器原生提醒；页内跳转不增加重复确认。浏览器临时存储受标签页、存储可用性和待办有效期限制，不能代替服务端保存或审批授权。

## 编辑配置：保存、放弃、继续编辑

对象、型号/规格、流程、场景模板、规则节点、Agent与触发配置沿用现有编辑页面。涉及未保存修改的离开统一提供：

- 保存草稿并离开：保存成功后再跳转；发布版本不因此改变。
- 放弃修改并离开：丢弃本次未保存内容，清除相应编辑缓存。后退不会重新出现已经放弃的内容。
- 继续编辑：留在原位置，保留填写。

菜单切换、切换用户端与管理后台、页内返回、浏览器返回、规格弹窗关闭使用相同的判断规则。刷新或关闭浏览器使用浏览器原生离开提示。只读查看、筛选、画布缩放不算配置修改。

配置未发生变化时，不要求再次确认，也不为了保存生成无意义的新草稿。保存失败时保留编辑内容、说明失败原因，不能一边显示保存成功一边离开。

编辑区显示“有未保存修改”或当前保存状态。界面恢复、草稿保存和发布是三个不同动作，不使用同一个状态代替。

## 同一任务的用户端与后台视图

任务详情中，有管理权限的用户可以点击“查看后台执行详情”；后台业务运行可以点击“查看用户端任务”。两边引用同一运行编号，当前身份不变。跨端后提供“返回原任务”或“返回原运行”。

用户端重点展示业务对象、当前步骤、谁需要处理、结果及下一步。后台重点展示执行记录、节点输入输出、来源证据和异常。两边继续使用同一业务状态，不新建一份任务。

顶部“用户端 / 管理后台”仍是工作区切换。草稿试运行只保留后台测试记录，不制造需要真实用户处理的任务。权限不允许时不提供对应入口；动作执行时再次检查，不能只依赖按钮隐藏。

## 返回与浏览器历史

一次完整的页面跳转只形成一次访问记录。例如任务进入关联对话，关闭任务弹窗的中间状态不再单独占据浏览器历史。

返回时恢复来源页面、任务、标签、筛选、滚动与查看位置。通知打开任务后，返回仍知道来自通知；跨端查看后返回到原详情。业务状态采用当前记录，不能随着历史返回变回“未审批”或“尚未执行”。

有未保存配置时，通过浏览器后退也必须先处理修改。选择继续编辑时，页面和浏览器地址留在原位置；选择保存或放弃后才进入目标位置。

## 来源对话与关联讨论

任务有可访问来源对话时，显示“返回来源对话”，打开原会话并定位本任务卡片。

任务没有可访问来源对话、但已关联可用数字人时，显示“在数字人中继续讨论”。点击后建立当前用户的关联会话，带入任务摘要与编号；任务本身保持原来源，不重新运行。已有讨论时显示“继续关联讨论”，复用该会话。

未关联数字人、原应用已停用或当前成员不可访问时，明确解释原因，任务仍可从我的任务查看，不擅自选择同领域另一个应用。

## 任务卡片按实际业务显示

普通任务卡片从运行记录读取实际业务对象、当前处理人、当前节点、最近执行步骤和下一步。简单重启审批不再套用“定位采集—诊断—复核—恢复”的固定四阶段，也不把已经明确的操作目标显示为“等待解析”。

BigData指标和TeleConnect会议继续沿用各自结果展示。未识别到设备时显示真实业务摘要，不凭空生成设备编号或假定诊断阶段。未知的新业务类型使用通用摘要与结果，避免搜索任务时因为缺少内置类型定义而报错。新增业务流程不需要为了任务卡片另建一套进度配置。

## 给开发人员的实现要点

复用三种公共处理即可，不增加配置菜单：

- 页面导航记录：保存来源和查看位置；一次跳转完成后统一提交历史。
- 编辑会话：保存基线、修改状态及保存结果；放弃清缓存，保存更新基线。
- 待办表单：按用户、运行、待办及依据版本隔离；恢复前检查有效性。

URL只保存页面和记录定位信息，表单内容、审批依据、凭据与完整运行结果不写入链接。后端仍必须检查当前用户权限、待办版本、处理幂等性和执行条件。

原型中的AI、外部接口、设备指令和通知为模拟。已保存的本地配置与运行属于当前浏览器和访问地址；不把本地链接称为跨设备共享记录。

## 本轮验证

本轮分开检查了代码逻辑、生成模板和 Chrome 实际操作。以下均通过：

| 检查范围 | 结果 |
| --- | --- |
| 编辑保护：放弃、保存、无变化、规格、对象、Agent、规则节点及保存失败 | 17 项 |
| 待办表单：两条 FBB 运行、成员隔离、依据失效、刷新、会议纪要与离页提醒 | 23 项 |
| 用户端：跨端同任务、关联讨论、来源权限及未知业务类型兼容 | 28 项 |
| 导航：历史返回、状态保留、放弃不复活、保存失败不跳转及返回时权限复核 | 16 项 |
| 原有跨领域任务、业务执行与 FBB 审批恢复回归 | 分别 35、25、26 项 |

Chrome 中实际操作确认了：

- 流程改名后通过浏览器后退，选择继续编辑、放弃、保存分别得到正确结果；前进回来不恢复已放弃内容。
- 型号/规格弹窗关闭时提示；继续编辑保留填写，放弃后重新打开恢复原值，无修改关闭不提示。
- 两条模拟 FBB 任务分别填写不同意见与处理结果，重新进入时各自恢复；任务 A 的内容不进入任务 B。
- 从任务查看诊断依据、后台运行详情后返回，保留同一任务及填写。管理员切换为其他成员后不显示原成员填写，也不显示无权使用的后台入口。
- 任务列表的搜索词与管理范围在跨端返回后保留。关联讨论后浏览器只需返回一次即可回到原任务，任务未重复执行。
- 保存状态即时更新；任务暂填状态可见。实际点击 Chrome 的刷新按钮出现原生离页确认，取消后保留内容。
- 本轮检查页面的控制台未记录错误或警告。

截图保存在 .prototype65/audit。逻辑回归包含模拟批准后的独立恢复；本轮 Chrome 的 FBB 检查重点运行到审批并验证表单、权限和往返，没有把它描述为生产指令执行验证。

HTML保持单文件交付。正式开发仍需实现服务端权限、任务并发与幂等控制、持久存储、外部接口、通知发送和真实执行；原型用交互与模拟结果表达这些边界。
