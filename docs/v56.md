# teleConnect 第56版：更新记录与功能说明

对应文件：[teleConnect_AI主动模式原型_56.html](</Library/Aiden/AIData/LLM Backend/teleConnect_AI主动模式原型_56.html>)。以第55版为基础，保留旧版。

本机预览：[第56版](http://127.0.0.1:4232/)。预览依赖本地服务运行。

本版面向开发人员理解配置、触发、状态变化和异常处理。所有外部接口、AI、工单、设备操作与通知仍是本地模拟；正式后台清单表示需要实现的服务端行为，不表示这些功能都缺少原型入口。

## 这一轮重点

- 规格配置集中到对象内：按业务需要启用规格，定义字段，再新增或导入配置。设备型号、指标口径和会议配置沿用统一结构。
- 对象列表在空间足够时直接展示查看、导出、归属与共享和删除；窄屏使用轻量菜单。
- 查看与编辑使用一致的能力、事件和关系列表及详情。概览压缩为必要信息，数量移到Tab；只读与编辑状态明确区分。
- 知识图谱增加关系创建入口，复用对象关系编辑器；支持选择目标和编辑模式拖线，不手工维护实际实例连接。
- 规则节点的基础信息和实现引用合并为节点配置；仅真实修改触发未保存提示。
- 满意的工作流可直接发布为场景模板，保留节点、连线、参数和固定依赖，不重复配置。模板发布不自动发布源流程或更新既有实例。
- 移除画布顶部独立“输入输出”入口；流程输入由开始节点维护，流程返回由结束节点维护，服务、Agent、子流程和试运行使用同一份契约。

组件固定值是该节点每次使用的配置；默认值是在缺少输入时按契约填补的值。外部传入的设备编号、来源系统、事件不能用一个节点固定值代替。流程输入与返回定义仍保留，只集中到开始和结束节点，避免重复维护。

## 拓扑查询：一个节点、三个出口

入口：流程编排 → FBB → “关联资源拓扑查询”。基础节点仍是“对象能力”，引用资源拓扑服务的“查询实际资源拓扑与监测覆盖”。没有新增FBB专属基础组件。

| 输入字段 | 来源与用途 |
| --- | --- |
| `source_system` | 开始节点传入的来源系统，确定资源命名空间 |
| `resource_id` | 身份查询返回的 `resource.id`，使用已经解析出的实际资源编号 |
| `direction` | 本节点配置的查询方向：双向、上游或下游 |
| `max_hops` | 本节点配置的拓扑查询范围上限 |
| `include_monitoring` | 是否查询监测系统对相关设备的覆盖关系 |

调用后首先检查返回是否满足固定能力契约，再按本次查询范围检查身份一致性、实际关系和监测覆盖。`complete` 表示业务数据完整性；HTTP成功或 `success:true` 只说明调用成功，不能替代它。

| 出口 | 触发条件 | 后续行为 |
| --- | --- | --- |
| 数据可用 | 本次查询成功，且 `complete:true` | 继续整理业务上下文和多源采集 |
| 信息不足 | 成功取得响应，但 `complete:false` | 保留资源与证据，进入“补充实际拓扑信息” |
| 调用异常 | 调用失败、响应不合规或校验字段缺失 | 进入已连接的异常处理，不生成完整拓扑 |

FBB直接复用能力返回的完整性判定，不再配置第二套条件。其他普通对象能力可以在“结果校验与出口”中选择已声明的Boolean输出字段，按同样方式分流。FBB的 `complete` 判定不可改成普通调用成功状态。

运行详情的“查询与结果校验”分别显示接口结果、校验范围、未满足项与实际出口。画布合并不会删除内部检查记录。

补充身份或拓扑后，配置中的“提交后重新执行”、画布连线和实际运行均回到原查询节点。补充备注只是核实依据，不直接改成外部事实；重新查询通过后才继续。身份/拓扑补充重查最多3次，达到上限仍保留问题，可转人工接手。任意循环仍不能发布。

## 诊断依据与能力匹配

入口：FBB运行详情底部的“追溯诊断依据”，或者用户端任务详情的“查看诊断依据”。

“诊断依据”展示本轮结论、继续处理/补充采证/人工复核的原因，以及每个故障组的目标、根因与证据引用。首轮只有候选时，显示待验证候选及已有告警，不提前展示补采后的诊断指标。分析资源显示运行记录中的Agent或模型编号、固定版本；新运行同时记录当时资源名称。

点击告警或诊断指标，可查看标准化字段、原始报文，以及对应采集请求和实现。这里是只读核对；人工修订诊断仍在待办中填写依据，不能修改外部事实。

“能力匹配”展开实际目标、来源系统、类型/型号、软硬件版本、能力实现及调用结果；有记录时可展开匹配路径。身份或拓扑缺口会显示原因，不从建模中心补造设备编号。

“来源回执”保留全部调用状态，成功但无告警的来源仍有原始回执。未形成编号的失败记录不会冒充有效诊断证据。

新运行按每轮分析保存证据快照。切回首轮不会混入后续采集结果；没有保存某轮证据时明确提示。旧记录没有历史快照时，说明只展示现存回执。返回操作回到原运行或原任务。

## 发布差异与引用升级

### 入口与操作

对象建模、流程编排、Agent 的“引用影响/引用检查”共用已有弹窗。右上角新增“评估引用升级”，不增加后台菜单。

选定对象及目标发布版本后，每个引用节点显示当前版本、目标版本、兼容性变化。默认不勾选任何节点；用户显式选择需要更新的流程或模板草稿。对象版本尚未发布、缺少所需能力或流程在当前领域只读时不能升级，不选择一个近似功能替代。

更新后显示每个流程的配置检查结果，并提供定位节点。跨流程定位前如存在未保存修改，会提示先保存或放弃，避免丢失编辑内容。当前打开流程的升级保留在编辑区，需点击页头“保存草稿”；未打开的流程写入其草稿。流程发布及Agent Release仍分别由用户确认，不随升级一起执行。

关联Agent列出可能受影响的应用：已发布应用仍使用原流程版本；新流程发布后，在Configuration/Release检查新依赖并发布应用。

### 差异规则

对象发布弹窗中的大段前后JSON替换为可读差异表。每行展示能力/字段、变化、原值、新值和影响。

- 删除输入/输出、改变字段类型、增加必填输入、输出由必填改可选：需要适配。
- 新增可选输入/输出：兼容变更。
- 结构/校验约束、默认值、请求位置、字段映射、解析路径、接口路径、方法、凭据、执行来源、风险或执行要求变化：需要复核。
- 没有契约变化：明确显示无变化，不凭版本号判断接口不兼容。
- 属性、事件、关系、分类、共享等其他对象定义变化也列入差异表；保留完整定义对比JSON折叠，防止摘要遗漏。

普通对象能力升级通过现有参数协调机制保留兼容绑定、自定义辅助参数，并新增来源字段；下游失效引用或缺少输入继续留在流程检查中。目标版本完全缺少能力时禁止批量升级，要求在节点中显式选择替代能力。

动态采集升级仅修改选中节点允许范围中对应对象的固定版本，运行目标仍由外部拓扑解析，不登记实际设备。

### 边界

界面是浏览器内模拟版本与草稿管理。旧发布流程、Agent已发布配置及在途运行不被修改。当前原型同一流程不同节点引用同一对象不同版本仍会触发原有冲突检查；可在升级列表显式选中相关节点统一版本。正式开发按节点独立解析版本，避免这项原型限制。


## 节点测试

入口：流程编排 → 任一节点右上角测试 → 输入准备中的“测试条件”。适用于对象能力、查询、HTTP、MCP、Skill、Agent及代码类节点；本地节点不展示网络超时等无关条件。

- 正常响应使用已保存的输入、固定契约、请求构建与模拟执行器。
- 调用/执行超时、返回不合规、必填输入缺失、版本不适配是当前窗口的明确模拟条件，不写入业务配置。
- 结果展示错误代码、发生阶段、检查依据及对应流程异常去向；输入/引用未配置好时先阻断，不能用模拟条件绕过。
- 多源采集可以按动态请求预览中的来源设置正常、超时、失败、无告警、过期；诊断采证不提供无告警选项。
- 按来源条件只挂在单节点测试运行上下文中；来源调用失败不生成成功证据。正常来源保留原执行器回执；过期/无告警沿用实际归一与质量检查。
- 结果增加来源概览、质量提示和当前窗口最近8次测试历史。反复测试各自使用干净的测试上下文，不耗尽正式采集尝试次数。
- 写入能力仍需完整流程的审批与授权，单节点测试不执行写动作。条件模拟不会创建真实工单、通知或调用设备。

AI“生成模拟上游输入”包含 evidence_quality，和完整流程采用相同含义；首轮尚无诊断指标时明确 complete:false。异常场景不会因缺少此必填输入而无法体验。

异常去向读取当前节点真实错误连线和端口名称。未连接失败出口时显示中断；策略与连线冲突时提示修复，不能仅凭一段说明声称已转人工。合并后的拓扑节点使用明确的“调用异常”出口。


## 客户端任务与运行办理

### 任务入口与办理反馈

任务详情顶部增加明确的来源与返回路径：从通知进入时返回通知；从任务列表进入时返回“我的任务”。详情内可查看执行进度，再返回原任务。客户端进度只展示当前用户可见的业务运行，不进入后台编辑器。

旧通知绑定原待办编号。若该待办已经办理或被新待办替代，打开通知后提示“这条通知对应的待办已办理/更新”，并展示当前最新任务，不能通过旧通知重复授权。

办理结果和错误保存在本次运行的 `client53` 中，关闭、重开或本地刷新后仍可查看。过期令牌、已被其他终端办理、无权提交、计划变化均保留明确反馈，不只显示短暂Toast。

审批详情提前显示超时、送审依据变化或证据过期的原因。依据变化或过期时移除“批准”选项；运行时仍使用原有指纹、令牌和身份校验，直接调用也不能绕过。超时只允许升级，不自动批准。

“工单、执行与恢复”折叠分别显示工单关联、操作回执和独立恢复证据。回执读取当前执行轮次的动作节点原始返回，恢复使用完整的告警、指标、目标和观察窗口判定，不能仅看接口 success。收到设备回执不代表恢复；没有可确认回执时进入“操作结果待核对”，实际提供查询原请求或转人工核对操作，不提供重复下发按钮。

### 如何体验

用户端 → 我的任务 → 体验FBB告警任务 → 接收模拟告警。创建时可选择正常、AI返回不合规、操作回执未知、来源不支持状态查询四种体验条件；它们只影响本条演示任务，不进入业务配置。

进入待办后，按界面显示的处理人切换演示身份，在任务详情中展开“模拟任务变化”：

- 另一终端已处理：用当前真实授权处理人的身份，在模拟运行中实际执行拒绝分支，转交人工；历史中保留该记录。此选项模拟同一授权账号的并发终端，不伪造另一个无权用户已批准。
- 待办超时：将这条演示待办的截止时间推进到过去，界面只提供超时升级，升级后走原流程人工分支。
- 审批依据变化：修改本次模拟诊断依据，保持原送审快照不变。依据指纹不一致后阻断批准；退回补证后重新生成审批。

这些控件只在明确通过“体验FBB告警任务”创建的演示任务、且当前用户为处理人时出现。普通业务任务不会出现模拟控件。

### 开发说明

通知、任务、执行进度和办理反馈共用运行标识。正式系统需要使用服务端的待办版本/令牌、身份权限、事务和通知状态实现同样的行为。这里继续采用本地模拟运行和浏览器持久化。

后端重复提交应返回明确的已处理结果；旧操作不得影响新的待办。当前原型保留旧令牌校验，并提示刷新读取最新状态。

### 审批材料与执行安排

审批节点自动从“批准”出口连接的执行节点取得当前计划，不要求再手工映射目标、动作、参数及版本。输入区显示这一来源，避免把“没有自定义输入”理解为“审批没有依据”。

审批卡默认展示触发对象、根因对象、操作目标、能力名称、固定版本、适用型号/软件版本和已识别业务；管理入口、实现编号、硬件及请求参数折叠查看。未能确认完整影响范围时明确标记，不把局部拓扑当成全量客户影响。

用户选择批准、拒绝、退回、挂起或恢复时，先看到“提交后会怎样”。更换退回位置，预览同步变化；恢复根据计划和证据时效判断是重新预检还是重查身份与证据。提交仍由运行端再检查，预览不是授权结果。

每次处理保留当时计划、操作人、结果、原因、返回位置、工单关联和轮次。挂起恢复显示“恢复后重新核验”，与“退回补充”区分；任务完成后的顶部反馈同步反映独立恢复结果，原办理历史保持不变。再次送审时可比较原计划和新计划；旧批准不能复用。任务列表和执行进度明确标识超时、依据过期、重新核验以及AI分析轮次。

### 待办指派

沿用节点现有的处理人配置，支持指定成员、任务负责人、发起人、上游负责人字段或平台团队。兜底处理人放在折叠配置中。待办显示实际命中的规则、处理人，以及是否使用兜底。

批准人可以不同于运行负责人，但必须是当前审批待办的授权处理人。执行端核对该人对应的有效批准记录、当前令牌及固定计划，不能因两人的姓名不同而误拒绝，也不能让普通负责人替代审批权限。

当前成员、团队和通知均为本地样例。正式系统复用平台组织成员和任务通知服务；团队分配、值班策略及成员有效性由平台服务端提供。

## 节点配置如何回显

打开任意流程或场景模板，点击节点即可编辑。业务名称、业务说明可以变化；基础类型、来源定义与固定版本保持独立。

回显的值分为三类：

| 类型 | 取值依据 | 如何修改 |
| --- | --- | --- |
| 来源定义 | 节点所引用的固定发布版，包括接口、契约、基础说明 | 在来源管理中修改并发布，然后显式更换流程引用 |
| 本流程配置 | 当前节点已保存的输入绑定、执行方式、映射与异常策略 | 在节点内修改，保存流程草稿 |
| 运行数据 | 外部参数、实际设备、动态采集目标、结果与证据 | 测试或运行后查看；配置阶段不伪造实际数据 |

没有选值时展示待配置；保存的选项已失效时保留原编号和错误提示。定义未明确声明响应格式、但存在结构化返回字段时，显示“JSON · 结构化响应契约”，不会把组件默认值说成来源明确设置。

### 设备身份与型号查询

此节点使用“对象能力”基础组件，固定调用“资源拓扑服务 v1.0.2”的“查询设备身份与型号版本”。

- 对象选择方式：固定对象。
- 执行方式：单次调用。这是流程编排方式，与HTTP方法不同。
- 请求：GET，完整地址由固定版本的baseURL与接口路径拼接。
- 入参来源：开始节点的来源系统、设备编号、可选序列号。原始事件是辅助上下文，未映射时不发送到接口。
- 返回：依据能力的响应契约解析；具体设备型号来自本次外部响应，不能把被调用的“资源拓扑服务”当成被查询设备型号。

“查看能力定义”展示固定版本的请求、返回、响应解析、成功/受理判断、风险和执行约束。凭据只展示引用标识。

### 动态对象与并行调用

普通能力可选“单次调用”或“按目标数组并行调用”。单次调用可选固定对象或引用上游的模型编号；上游值必须属于允许对象范围，且对应固定版本中存在该能力。

多源告警采集与按需诊断采证仍使用同一个对象能力基础节点。配置页列出允许对象及固定版本，测试/运行展开实际动态任务：实例身份、来源系统、匹配实现、请求参数、解析结果与成功/失败回执。设备数随外部拓扑变化，不能用静态A/B/C分支代替。

对象版本可以显式选择；更换版本保留兼容参数绑定、自定义辅助字段和稳定字段标识，不兼容项留待修复。正式开发应以每个节点的版本引用解析执行定义；当前原型同一流程同时引用同一对象的不同版本会阻止发布，避免共用对象快照覆盖。

### 响应解析

默认继承固定能力契约。对象建模的功能“返回定义”可声明JSON或文本格式；旧定义按结构化字段识别JSON。文本格式要求来源返回契约为`text:String`。

节点允许显式设置解析格式，但不得与来源契约冲突。无格式、错误格式或文本/JSON不一致会阻止发布和调用。输出字段的JSON路径、上游引用或固定返回值仍在“输出”中维护。

### 其他基础节点

- 旧查询/功能节点：固定对象版本或原发布流程对象快照；原接口名称、地址和字段定义一致。
- MCP Tool / Skill / Agent：名称、说明、输入输出来自保存的引用快照；目录缺少固定版本、资源停用时保留原引用并阻断新版测试/发布/调用。
- AI分析：显示选择的Agent或大模型及固定版本。旧式LLM组件没有独立版本时明确说明，不显示虚假的固定版本。
- HTTP：回显方法、地址、凭据引用、解析策略以及已配置的输入输出；自动解析与强制JSON/文本分别标明。
- 子流程、关系查询、循环与批处理：保留已选版本、目标与映射；已删除的候选项不会使选择框默默改选。
- 本地条件、字段处理、审批与信息收集：回显原业务配置和异常/等待策略；没有接口的节点不增加无意义的HTTP字段。

次要来源信息放在“生效配置与来源”折叠中，不扩大画布卡片。

## 图标规则

图标由基础节点类型决定，不由节点业务名称、对象名称或本次实例决定。比如“设备身份与型号查询”“关联资源拓扑查询”“多源告警采集”“受控设备操作”均为对象能力，始终使用同一立方体图标。

不同基础类型使用不同SVG几何形状；查询、对象能力、HTTP、MCP、Skill、Agent、条件路由、审批、采集、代码等不再混用通用文档或扳手。节点管理、添加节点、画布、详情和节点信息弹窗共用同一图标注册表。独立注册的业务组件与其基础工具有不同定义编号；其图标也独立。自定义定义生成稳定标识图标，重命名不变。

## 开发实现要点

前后端应共用一个有效配置解析结果，至少包含基础节点ID/版本、资源ID/版本、对象能力及版本、输入输出契约、输入映射、解析策略、执行和异常配置。编辑器、请求预览与运行端不能各自查不同来源。

发布时校验固定引用、权限、契约、版本和下游影响，形成不可变运行快照。查看草稿可以保留无效引用用于修复；运行不能回退到最新版本。恢复在途任务沿用原快照与审批依据。

所有入口——新建流程、复制、模板创建、导入、添加节点、保存——使用同一套作者态迁移。历史发布快照和已开始的运行不自动升级。本版保留JSON编辑、导入导出、自定义字段及跨领域流程。

## 基础配置体验路径

- 流程编排 → FBB → 编辑“设备身份与型号查询”：在参数详情中查看或修改显示名称、说明、取值来源与请求用途；通过请求预览核对实际发送的内容。
- 节点右上角更多 → 节点信息：查看该业务名称背后的基础节点与引用能力；对比“设备身份与适用版本检查”的条件路由职责。
- 节点详情标题下编辑节点说明，保存草稿后再次打开；基础定义及其他流程中的节点说明不随之改变。
- 展开执行与异常，查看当前节点适用的设置；技术失败与信息不足各走对应处理路径。

## 用户端：我的任务与主动提醒

用户在TeleConnect内使用已发布Agent及工作流。“我的任务”负责人的办理和进度，“主动提醒”保留会议、邮件、经营预警等原有建议卡片。不要把普通提醒当成已经创建的审批待办。

任务列表按“待我处理、我发起的、我负责或参与的”查看，并按运行状态筛选或搜索。外部告警启动的FBB即使没有Agent会话，也能出现在负责人员的任务中。管理员的全局排查仍在后台运行中心。

点击任务先看业务摘要：业务/设备、当前进度、根因结论、拟执行动作、风险、处理人、截止时间与关联工单。处理表单只展示当前步骤需要的内容；历史与技术详情折叠。

### 谁负责什么

| 角色或位置 | 职责 |
| --- | --- |
| 流程设计者 | 配置节点、输入输出、处理人、允许结果、退回位置和时限 |
| 任务发起者 | 发起任务，查看进度，处理明确分配给自己的补充事项 |
| 待办处理人 | 核对依据并完成审批、补充、复核或现场处理 |
| 管理员 | 排查配置/接口问题，查看全局运行及审计；普通客户端查看不代表拥有审批权 |
| 运行引擎 | 校验权限与令牌，保留固定快照，更新状态，继续执行或等待 |

### 审批、退回和挂起

审批针对当前展示的设备、动作、参数和能力版本。批准后仍须通过执行前校验；拒绝后保留关联工单并转人工；退回只能选择流程允许的业务步骤。

挂起的是当前待办及其依赖的后续操作，不是撤回已经发出的设备指令。填写原因，按配置显示提醒和截止时间。恢复重新检查，计划变化或证据过期则重新查询并再次审批。挂起不自动暂停故障单SLA，也不代表所有独立并行分支都停止。

信息补充、诊断复核和现场处理使用同一任务详情。用户提交的说明只是本次运行证据，不能自动变成对象定义或长期资源关系。对象契约缺失、平台资源不可用等配置问题交给管理员，不让普通用户通过填写备注绕过。

### 通知、会话与任务的关系

进入等待后生成待办并通知处理人；会话卡片、通知和列表引用同一个运行与当前待办。打开或标记已读只更新通知状态，不改变审批结果。待办已完成、转向或令牌已更换后，旧通知打开最新状态，不能再次使用旧操作。

任务列表中的待处理数量与未读通知数量是两个概念。挂起继续属于待处理；任务完成后从待处理退出，但结果通知可以仍未读。

父任务与故障子任务各自拥有运行编号，通过父运行与故障组标识关联。待办只由对应任务的当前处理人办理；父任务查看进度不代表可以代替每组审批。

原型在本地生成通知和记录，不会发送真实消息。提醒、超时、客户端关闭后的可靠运行，正式开发应使用服务端持久任务和调度；不能依靠浏览器保持打开。

## 领域管理与分类

领域树支持OSS、BigData、TeleConnect、公共域及其子领域。页头领域筛选作用于可见对象、节点、流程与记录；共享引用需有明确授权。

“领域”回答业务归属，“对象分类”用于列表组织，“父类型”表达语义上的一般与特殊。三者不能混用。厂商、型号也不等于网络拓扑的上游与下游。

领域统一约束是流程不能放宽的基线，例如只读、禁止的动作、执行时间窗、目标白名单与最低执行可信度。流程设置可以进一步收紧。原型不另设独立“业务策略”菜单。

## 维护信息：谁创建、谁修改

需要长期维护的对象、型号/规格、领域、规则节点、流程、模板、Agent配置及知识案例，使用统一的维护信息。详情展示创建时间、创建人、更新时间、更新人；列表采用更新时间摘要和“维护信息”入口，避免四列元数据挤占业务内容。

这些字段由保存动作自动维护，不要求用户手填。新建记录保存创建人与创建时间，修改保存更新人与更新时间。仅查看、搜索、测试或运行，不应改写配置维护信息。流程或对象的发布版本、发布人及发布时间仍在版本记录中查看，与草稿的最后修改区分。

历史配置中缺少的创建信息显示“未记录”；旧查询缺少查询人显示“历史未记录”。不能把导入旧数据或升级原型的时间当成原始创建时间。原型在浏览器中保存这些记录，正式系统应使用服务端时间、登录身份和审计事务。

## 对象建模

### 一个工作区

进入“对象建模”，左侧是类型树，右侧显示所选类型的定义摘要、直接子类型和适用型号/规格。

点击箭头展开或收起；点击类型名称选择类型。数字表示当前范围内的直接子类型数量，不表示实际设备数。右侧路径可以回到上级类型。树支持方向键、Home、End和Enter。搜索时自动展开匹配路径，此时全部展开/收起暂不可用，清除筛选即可恢复。

例如：网络设备 → 接入设备 → ONU/ONT；工单 → 故障单/施工单。分类和领域作为筛选维度，不作为人工插入的父节点。区域、站点、板卡、端口之间的安装或组成关系仍在关系配置与知识图谱表达。

搜索名称、编码或型号信息后，匹配的规格会定位到所属类型，祖先保留并标记为“上级路径”。领域可见性校验仍生效，不为拼出完整树泄露范围之外的对象。型号筛选字段由类型配置动态生成。

类型总览和规格列表每页15项；规格字段的“可筛选”控制筛选入口，“列表列”控制列表显示，详细配置仍可在规格详情查看。

OSS设备可按厂商、管理方式筛选；BigData指标按数据系统、周期等字段筛选；TeleConnect会议可按会议类型、组织等字段筛选。不会强制所有领域填写设备厂商。

没有型号层的对象，直接维护类型契约即可。复制、JSON编辑、导入导出用于复用配置，不再要求建立额外“对象模板”层。

### 查看、能力与编辑共用一处详情

点击对象名称、“查看”或“查看能力与事件”，进入同一对象详情；能力入口直接定位到能力页签。宽桌面的列表直接展示查看、导出、归属与共享、删除；较窄视口才把低频操作收进小菜单。删除仍经过依赖检查。

详情包括概览、能力、事件、关系、规格配置和常用查询。能力、事件、关系列表与编辑状态使用同一组件；查看状态提供“查看详情”，编辑状态再显示新增、修改和删除。能力和关系详情复用原有表单字段，查看时转为可读文本，仍可切换信息页，不出现保存或执行操作。

概览不再使用能力、事件、关系的大型数量卡片，数量放在页签。主体显示紧凑的基本信息、实例身份、对象属性和维护信息。属性、事件详情从同一套字段定义生成，避免查看页与编辑页各维护一套内容。

默认只读查看已保存草稿，也可选择具体发布版本。点击“编辑草稿”才进入编辑缓冲；仅查看和切换页签不会改变定义或触发保存提示。保存草稿、发布检查、未保存离开提示继续沿用已有机制。入向关系由其他起点对象维护，不能在当前对象内修改对方定义。

新发布对象同时固定规格字段、显示名称和当时已发布的规格目录快照。以后修改配置名称、字段或规格草稿，不改变该历史版本的回显。旧对象版本没有独立规格快照时，明确标记按其发布时目录历史展示；没有对应目录历史时显示缺失，不取当前草稿补齐。

现有对象支持历史参数结构：有契约时展示契约；只有旧字段定义时按原字段展示。某些早期能力尚未定义参数或说明，会明确显示缺失，不能将其说成已验证的零参数接口。FBB实际引用的资源服务、采集和工单能力继续按固定契约回显。补齐旧能力必须依据真实接口配置并单独发布。

实例定位优先展示结构化身份规则；只有旧标识说明时显示原说明，并提示尚未配置接口字段映射，不从中文说明猜测字段名。

### 在对象内定义规格

操作路径：对象建模 → 查看对象 → 规格配置页签 → 编辑草稿 → 字段与启用设置。每个对象都有入口，未启用时显示用途和启用操作，不必先去全局导入猜测支持什么配置。

规格是可选的差异配置。设备可命名为“设备型号”，营收指标可命名为“指标口径”，会议可命名为“会议配置”；名称由当前对象维护，沿用统一的数据结构和能力实现机制。普通对象只需要共性契约时可以保持关闭。不会为不同领域再增加设备专用页面或新的对象类别。

字段与启用设置包含：

- 上级类型：按名称、编码和路径搜索，排除自身和后代，保存前再次校验循环。
- 启用差异配置及配置名称：按业务需要设置。已有规格记录时不能直接关闭。
- 字段：编码、中文名称、数据类型、必填、可筛选、列表展示；JSON模式可定义嵌套结构、数组元素与枚举。
- 兼容性：删除仍有值的字段、改为不兼容类型、新增却未补齐的必填字段会阻止应用，并提示受影响的配置。

可视化字段与JSON双向同步。“应用到对象草稿”只更新当前编辑区，点击页头“保存草稿”才保留；退出并放弃修改会同时还原对象内容和规格字段设置。修改未完成时可以继续编辑，不会暗中保存其他字段。

字段定义保存后，在当前对象的规格页签中新增、编辑、导入或导出配置记录。进入这些独立保存操作前，若对象本身仍有未保存内容，先通过已有保存/放弃提示处理，避免将其他未完成修改一起保存。

这些检查保护当前类型的配置结构，不等于自动迁移全平台依赖。正式后台须在服务端重复校验，并以版本事务保存对象、字段和发布快照。

### 类型、型号与实际实例的关系

- 类型定义共性，例如ONU、OLT、端口、光路、营收指标、会议。
- 型号/规格定义适用差异，例如某型号ONU、某种统计口径。它是可选的配置层，不是整个对象体系的最后一层。
- 能力实现声明具体型号、实际版本和管理方式下如何履行公共能力契约。
- 实际设备编号、序列号、当前软硬件版本与真实连接由OSS/EMS/资源系统在运行时返回。

“ONU属于网络设备”是类型语义；“设备X连接端口Y”是实例事实。前者不能推出后者。设备、板卡、端口、分光器、光路可以继续相互组成或连接，不必在型号处停止建模。

工单是通用业务类型。施工单用于安装、开通、改迁等现场作业；故障单用于告警或投诉后的故障处理。故障修复若需要施工，可关联施工单；施工完工不等于故障已恢复。

### 标准对象结构

“资源拓扑服务”“告警系统”继续沿用既有对象结构：编号、名称、编码、分类、领域、属性、功能、事件、关系、来源等字段不另造格式。型号/规格仍沿用统一记录结构，其扩展字段放在配置中。

属性描述字段含义与结构，允许有`instance_id`或设备编号等属性定义；这不表示在建模中心逐台登记该字段的真实值。

### 型号字段从哪里来，如何与JSON同步

“对象类型”不是从任意JSON字段名猜测得到的。规格采用统一结构：`t / id / name / p`，所属类型放在`p.object_type`，值是对象类型编号，例如`onu`。界面用该编号查找对象定义并显示“ONU / ONT”。旧兼容字段`p.device_type`必须与它一致。

厂商、管理方式等扩展字段来自该对象的“字段与启用设置”：字段编号决定`p.config`里的键，字段名称决定中文标签，类型/必填决定校验规则。例如字段`management`的中文名称为“管理方式”，值保存在`p.config.management`。BigData和TeleConnect可以定义自己的字段，不强制沿用设备字段。

配置记录中编辑的是字段值。新增字段或修改中文名称、类型、必填，应先修改当前对象的字段定义，再在配置中填值。JSON出现未定义字段时会提示，不能悄悄新增表单字段；导入时可把它映射到已有字段，或明确选择忽略。

表单→JSON：切换JSON编辑时生成当前配置；修改厂商/管理方式会同步旧兼容字段。JSON→表单：解析并校验后同步，结构或类型错误继续停留在编辑状态。已有编号不可从JSON绕过限制；从对象内部新增或导入配置时，所属类型始终锁定，JSON也不能换成其他类型。更换类型需要新建配置并评估引用迁移。

领域由所属对象定义提供，发布状态通过草稿与发布快照对比得到，不作为用户可改的运行状态。保存始终生成草稿；发布时单独检查。

### 能力继承来源与本级覆盖

入口：对象类型摘要的“引用影响与继承来源”，或规格详情的“能力继承来源”。

同名能力不自动等于继承。现有类型中各自独立定义的能力标为“本类型定义”；若上级也有同名能力，会明确显示上级名称，不伪造继承关系。

选择“引用上级已发布契约”，先选来源类型/能力，预览固定版本、输入输出数量，以及新增还是替换本级同名草稿。确认后保存显式引用；原有发布版本不变。

引用使用功能内的可选元数据`inheritance47: {ownerId, capability, version}`，并保留一份固定来源的输入输出契约。它不是新对象结构，也不是生产实例记录。正式实现建议用统一的契约引用字段，不把演示版本后缀当作后端设计要求。

- 固定上级发布版本，不跟随上级草稿自动改变。
- 引用输入输出及操作性质，不自动获得管理入口、型号实现、白名单或执行许可。
- 本级可配置自己的执行入口；新增引用未配置入口时不能发布。
- 引用契约不能直接改成另一套输入输出；保存和发布都会检查。需要覆盖时，先“转为本级定义”，再独立编辑、检查及发布。
- 来源版本不存在、不再属于上级类型链、契约偏离固定来源，会进入发布检查。
- 写能力引用不会获得自动执行授权，仍需要原有审批、策略与恢复校验。

### 能力定义与差异实现

功能定义维护公共请求/响应契约、HTTP方法与路径、鉴权引用、成功判定、风险、审批及恢复验证要求。

型号/规格下可维护多份实现：适用硬件、软件或其他条件、实现版本、管理入口、协议/资源引用、请求模板、输入输出Schema、前置检查及验证方式。实现可配置HTTP适配，也可引用已有MCP Tool、Skill、Agent或代码能力。

从对象内的规格配置记录进入“能力实现”，沿用原有能力配置页面，以表格并列展示公共能力与契约、当前规格的实现与适用条件、配置操作。可按名称或编码搜索，以及筛选未配置实现、只读或可能变更状态的能力。

“查看契约”打开类型的输入输出定义；“添加实现”创建绑定当前能力的草稿，不把旧的重启模板误当成新能力；“配置实现”修改具体实现；“测试匹配”检查当前能力与适用条件在已发布目录中是否有唯一匹配。

没有本规格实现时显示“未配置本规格实现”，不会显示为已继承可调用。匹配测试不登记实际设备，也不下发指令；发布状态和适用条件是两件事，存在已发布实现仍需核对真实运行版本与管理入口。

运行匹配必须唯一。型号不存在、类型不符、软硬件版本不支持、多个实现同时适用、实际管理入口不匹配，都不能选择“最接近”的实现继续。当前示例中LAB-HW-1、LAB-A/B、SIM-1是测试基线，不是厂商真实固件版本。

端口能力可按已返回的唯一所属设备来解析适用型号；所属关系不明确时暂停，不能随便选择一台设备。无源光路不能因为关联了可重启设备就获得重启能力。

### 关系配置怎么用

关系同时定义业务意义和获取实际关系的方式：起点类型、终点类型、关系名、反向名称、数量限制、只读来源功能、起点入参、关系入参、返回数组与目标编号/名称映射、有效期。

例如“告警系统监测ONU”与“ONU接入OLT”是不同关系；“告警属于设备”又是另一种关系。关系来源可能同为OSS接口，但返回内容不能相互替代。

点击关系编辑，先选起止类型，再选有契约的只读来源功能，配置请求字段与返回路径。下拉选择支持搜索；发布检查会核对功能、字段类型和返回数组是否存在。

关系测试使用外部模拟响应，输入起点编号后只解析该响应中对应关系。不存在的边返回无结果，不能借用其他关系或从父类型推导。知识图谱连线的侧栏可打开同一个关系定义弹窗；编辑定义不会改写外部真实连接。

### JSON、导入、草稿与发布

“导入对象定义”第一步为“对象配置”，支持上传JSON或直接粘贴JSON。解析后进行映射与配置，最后检查变更并确认导入。没有解析到依赖时使用“在对象配置信息中暂未解析到外部依赖”，不宣称外部一定不存在依赖。

对象内“导入配置”与全局批量导入使用同一个 `teleconnect.object-config` 配置包，包含标准 `t / id / name / p` 记录、字段定义参考及可选的能力实现。对象内部入口固定所属类型，错误类型会提示使用正确对象或全局批量导入。

导入先解析配置，再核对编号、字段匹配和外部依赖，最后预览并确认：

- 同名字段自动匹配；未识别字段必须选一个已有字段，或明确选择忽略，不自动创建字段定义。
- 缺少必填、数据类型不符、多个来源字段映射到同一目标、编号冲突均需修正后继续。
- 管理入口、MCP Tool、Skill、Agent等外部引用需要对应到可用资源；不满足依赖时不能提交。
- 类型配置随包提供参考，不自动覆盖本地对象字段。配置摘要、身份编号、扩展字段各有固定位置，不把任意JSON键当作对象类型。

导入仅创建配置与实现草稿。对象内“导出配置”包含该对象的配置记录及相关实现，原全局导入入口保留。模型配置包拒绝实际设备和业务实例台账；测试实例仍放在“测试数据”。

修改尚未完成、未通过检查或尚未准备让新业务使用时，保存草稿。发布时显示检查结果、差异与依赖；已有发布版本继续可用。流程固定配置版本，不会因对象产生新版本就自动升级，Agent也固定所选择的流程版本。

## 规则节点与流程编排

### 规则节点的配置与使用位置

规则节点目录将“基本信息”和“实现与引用”合为“节点配置”。上方维护名称、说明、分类等公共信息，下方按实现类型显示对象能力、平台资源、HTTP或代码配置。内置组件显示公共职责和运行方式，每个工作流中的具体参数仍在流程节点内维护。

输入输出、执行设置、测试与发布和统一定义页继续保留。引用来源不再独占一个页签；“使用位置”按钮集中列出哪些流程、哪些节点引用了该定义及其固定版本，并支持定位到对应节点。

未保存状态按完整定义与进入编辑时的基线比较。仅切换页签、打开查看和恢复原值不会提示保存；真正修改名称、说明、输入输出、源码、来源、固定版本或执行设置时，才提示保存、放弃或继续编辑。草稿和发布快照仍隔离。

### 从流程发布场景模板

入口：流程画布右上角“发布”的下拉菜单 → 发布为场景模板。已配置满意的工作流可直接复用，不需要在场景模板再重新搭节点。

默认选择当前已发布流程版本，也可明确选择历史版本或当前草稿。发布版本有固定来源，不会在操作中自动切成最新版本；当前草稿须检查通过，并有与当前定义完全匹配的通过测试。

新模板复制节点、连线、输入返回契约、诊断规则、执行配置和固定依赖，生成独立编号、版本和发布快照，并记录来源流程及版本。默认只在本领域使用。个人测试输入、运行记录、审批会话、运行上下文和原模板使用计数不复制；原型定义中配置的模拟返回可以保留，但不视为真实接口数据。

FBB的14类诊断响应样例随模板保存为独立测试资源，基于模板创建的新流程也保留独立副本。来源流程后来修改样例，不改变已发布模板。缺少正常或异常响应样例时明确报错，不以健康期望值补齐；否则会把已有故障错误地显示为无故障。样例可从现有“测试数据 → 诊断响应样例”入口查看与调整，不新增配置页面。正式开发时将模拟资源与模板版本关联，生产运行仍读取真实外部响应。

已存在同源关联模板时，可明确选择发布其新版本；不能覆盖无关模板，也不会因为工作流曾从某模板创建，就自动改动原模板。更新时保留模板使用次数和置顶状态。完成后可查看、体验模板，或基于模板创建新流程。

发布模板不顺便保存或发布源流程，不升级Agent的固定流程引用，不修改已经创建的流程或在途任务。正式实现应复用流程检查服务，在同一发布事务中校验权限、领域、依赖、测试匹配和预期版本，阻止并发覆盖。

### 流程接收参数和返回结果

画布顶栏不再保留独立“输入输出”按钮。开始节点展示“流程接收参数”，通过“编辑输入字段”维护；结束节点的“输出”提供“编辑返回字段与取值”。两个入口使用同一个编辑组件，分别处理输入与返回。

字段支持名称、中文显示名称、说明、类型、必填、默认值、嵌套JSON Schema、添加与删除。也可直接编辑字段数组JSON，或解析示例JSON对象生成字段。服务、Agent、子流程和试运行统一读取 `interface29.inputs / outputs`，开始与结束节点只是它的编辑入口和运行投影，不维护第二份契约。

默认值只在请求没有提供该键时使用。已经传入的 `false`、`0`、`null` 不会被默认值覆盖；这些值是否有效仍由字段契约判断。每次运行的设备编号、来源系统与原始事件来自外部请求，不能用一个节点固定值替代真实身份。

多个结束节点共用返回字段结构，但分别保存取值映射：本节点结果、当前分支上游变量及子路径，或固定值。修改公共字段后同步到所有结束节点；新增返回字段需核对其他分支的映射，不能引用当前分支不可达的输出。输入删除继续检查已有引用。

“描述与服务”展示只读输入/返回摘要，并提供定位开始节点、定位结束节点。服务调用测试仍针对明确的已发布版本；编辑草稿不会改变已经发布的服务、Agent或在途任务。

开发时可让各结束节点按字段名存储取值方式和路径，先完成映射，再校验公共返回Schema。入口默认值处理也应共用一套逻辑，避免服务、Agent、子流程使用不同规则。

### 通用节点

保留查询/对象能力、HTTP请求、MCP Tool、Skill、Agent、知识检索、AI分析、代码、字段/JSON转换、条件分支、循环/批量、并行、子流程、信息收集、人工审批、通知、结束等组件。图像及音视频处理组件不在本轮范围。

对象能力节点统一选择对象及已发布功能，可以单实例调用，也可以接收数组进行批量并行调用。查询对象功能与新增能力引用共用此入口；避免再创建一个功能相同的“设备型号调用”节点。

MCP、Skill、Agent使用统一资源选择与引用方式，在节点配置中选择资源及固定版本。已有工具能直接完成简单查询时，无需额外包装Agent。规则节点管理维护组件与分类，资源本身仍由平台原有资源管理模块负责。

代码节点支持JavaScript、Python、Java编辑、输入输出和模拟测试；JAR/Python文件上传可走原型配置、校验、发布及加入流程。页面内不代表已具备真实JVM/Python执行环境。

### 输入输出与节点编辑

点击节点，在连续侧栏中维护当前节点说明、输入、处理配置、输出及执行与异常。开始节点明确展示流程接收参数，事件、API、Agent使用同一份输入契约。

“可引用的上游数据”默认展示前4项紧凑摘要，来源和类型在同一行，完整路径可悬停查看。点击“查看全部并添加”可搜索、展开节点字段树并选择字段。只有选用的字段才加入当前输入，不再把全部上游返回逐节点复制。已经使用的契约字段、实际处理字段和手工新增字段保留。

例如，拓扑查询默认5个请求输入；AI故障分析使用6个实际分析输入；独立恢复查询使用2个请求输入。审批由固定计划驱动，异常处理自动接收失败节点、错误、原请求及已成功取得的证据，因此它们可以没有额外自定义输入；这不是丢失运行上下文。

字段树能够直接选择 `设备身份与型号查询.resource.id`，其类型为String。不存在的子字段、Object绑定到String等不匹配会在JSON应用前或发布检查中报错。已知结构严格检查；没有声明结构的JSON仅标为动态数据并在运行时核对，不假定它一定含有某个字段。数组支持整组引用，逐项值由批量节点配置，不自动取第一项。

条件节点可以没有业务输出：它只选择出口，判断输入和分支保存在运行记录，后续节点仍可直接引用前面的查询结果。受控重查回路属于控制关系，不会让当前节点把自身或本次尚未执行的后续输出当作输入。


每个参数分别维护字段名、显示名称、参数说明、类型、必填及值来源。字段名供程序和接口引用；显示名称是简短业务名称；参数说明解释含义和要求。来源系统`source_system`的实际值仍来自所选上游引用，不会取界面中文标题作为值。

引用对象能力或上游参数时，带入来源的显示名称和说明；当前节点可覆盖展示信息，或恢复为来源说明，不修改来源能力本身。同名字段在不同节点可有不同含义，例如身份查询的`candidates`表示候选设备，故障分析中则表示故障候选。历史字典只用于已有示例的初始化。

输入参数有两个独立维度：取值来源决定从上游、固定值或运行上下文取得什么值；参数用途决定它仅供本节点处理，还是映射到对象能力的某个请求字段。新增辅助字段不自动扩展源接口。选定对象请求用途后明确选择目标请求字段，保留对应版本与契约约束。

自定义输入输出可增加、删除和调整说明；来源要求的必填字段、类型和嵌套必需结构仍受校验。字段别名与请求目标分别保存；删除被下游使用的输出先展示引用影响，再保留失效提示供修复。未解决的引用、类型或请求映射问题可保存草稿，不能发布。

默认值须明确启用，仅在字段未提供时使用。`0`、`false`、空字符串和`null`不被无差别替换；引用不存在或路径无效时提示错误，不能通过默认值掩盖错误。

引用字段的默认值还须证明来源节点已执行，且缺少的是来源结构中声明的选填字段。必填字段未返回、数组越界或子字段拼写错误会阻断，不能补一个默认值就当作接口成功。

JSON编辑区分输入/返回样例与参数定义。样例用于解析字段、类型及值或引用；参数定义用于维护名称、说明、Schema和映射等元数据。两种方式都先解析预览再应用，失败保留已有有效配置。仅凭样例值不会自动产生准确中文业务说明。

AI的最新已校验证据和证据质量属于本次运行来源，受字段类型、实际采证路径和适配器检查，不伪装成单个上游节点的输出。未声明的运行字段无法通过检查。

### 参数工具栏、搜索和增删

节点侧栏与代码IDE使用同一套输入输出参数编辑器。顶部放“从上游选择”和“JSON 编辑”；搜索独占一行，明确标注搜索当前输入或输出，并显示匹配数、清空及无匹配提示。它只筛选显示，不删除参数。原截图中被截断的输入框即这个参数搜索，不是接口输入值。

最后一个参数下方提供“添加输入参数”或“添加输出参数”，空列表保留同一入口。新增后展开所属区域、清除会隐藏新字段的筛选，按字段稳定编号滚动定位、聚焦字段名并短暂高亮。上游批量添加显示实际加入数量与来源，可定位下一个新增参数；已存在的字段不重复加入。

参数卡片右上角的“删除”作用于整个参数；嵌套结构的“删除子字段”只影响该子字段。来源契约要求的必需字段显示锁定原因。删除仍被下游使用的输出仍须处理引用影响，不能绕过发布检查。普通删除可撤销；后续又进行了其他编辑时，使用画布撤销按顺序恢复，避免覆盖后续修改。

开始节点的接收字段、结束节点的返回字段以及规则节点目录的参数，也保留末尾添加和明确删除操作，并提供新增定位。

### JSON、长文本与代码的阅读和编辑

只读JSON查看器显示格式、总行数和大小，提供搜索、复制全部、自动换行和展开查看。其他较长的只读文本使用同一展示方式。预览有合理的高度上限；展开后使用接近全屏的区域，避免一大段内容藏在几行高的框里。

JSON、Schema和长文本编辑区通常使用约280—400px的初始高度，提供行数、扩大编辑及适用时的JSON格式化；短说明和字段绑定值不机械撑高。扩大编辑读取当前尚未保存的文字，“完成并返回”或Esc写回原输入框，并执行原有草稿更新或校验逻辑。扩大操作本身不额外发布配置。

只读内容扩大后仍只读；代码节点继续使用已有IDE。JSON格式化只调整排版，不能代替“解析并预览/应用”的结构检查。剪贴板不可用时明确提示手动复制，不假报复制成功。

### 基础节点与当前业务节点

画布名称表示该节点在当前流程中承担的业务步骤；基础节点定义决定它支持哪些配置与执行行为。更多菜单中的“节点信息”展示真实基础名称、用途、分类、版本，以及实际引用的对象能力或MCP/Skill/Agent。

例如，“设备身份与型号查询”使用基础“对象能力”，引用资源拓扑服务的查询设备身份与型号版本能力；“设备身份与适用版本检查”使用基础“条件路由”，读取前者的完整性结果并选择出口，不重复查询设备。

侧栏标题下可编辑当前节点说明。修改它只影响当前流程草稿；基础定义说明由规则节点管理维护，发布后再由流程选择适用版本。查看来源定义和引用能力时应保留返回当前节点的上下文。

### 请求预览、测试和运行

对象能力的请求预览、单节点测试和完整流程使用相同的请求构建规则，按当前固定版本的契约及明确映射生成请求。预览同时显示节点输入和实际请求，辅助字段不自动发送；请求字段不能靠同名的隐藏回退绕过用途配置。

测试入口仍采用输入准备、请求与目标、结果与回执三步。预览不调用接口；单节点测试中的写操作仍需回到完整流程验证授权。批量采集保留每个目标的能力实现、版本、请求和结果，不能用一个来源的成功覆盖其他目标失败。

### 执行与异常

执行与异常按节点能力展示适用配置，复用已有运行设置，不复制一套互相冲突的超时与重试值。

外部调用配置请求超时、重试和失败去向。重试耗尽后停止或进入明确连接的异常出口，不生成假成功响应。写操作的自动重试必须满足已发布能力的幂等约束；未声明时不开放通用重复执行。

并行采集额外明确并发、必需来源及部分失败规则，保留成功证据。AI调用失败或返回格式错误属于技术异常；诊断证据不足属于业务判断，继续走补证或人工复核分支。

审批和信息收集使用办理时限、提醒、超时升级、挂起与恢复设置，不解释为网络重试。条件路由与字段整理处理表达式或数据错误，不提供无意义的HTTP请求重试。

### 精简后的采集节点

新增或编辑“对象能力”节点，通过“能力使用方式”选择普通调用、多源告警采集或按需诊断采证。切换时保留兼容绑定和自定义字段，可切回原来的对象功能调用；没有当前流程的拓扑输入或场景需求时，显示缺口并阻止发布，不借用FBB配置。

FBB批量采集的输入是实际拓扑或按场景需要形成的资源集合，内部按可信身份、类型、型号、实际版本和管理方式匹配已发布实现。

用户主要配置：采集对象、采集能力或证据需求、请求参数、返回字段映射及完成要求。任务生成、调度、汇总和技术校验是组件内部可追溯的执行阶段，不另画多个流程节点，不另建分组配置或第二套流程。

基础采集查询告警；补充采证按候选的缺口查询光功率、OTDR、日志、配置、认证、路由或性能等。两者共用组件与数据约定。只有只读采集使用此批量路径；修复指令沿用独立受控执行与审批。

每项结果保留目标、来源、能力、适用实现版本、请求、原始响应、时间和状态。成功但无告警、失败、超时、过期、未返回分别表达；部分失败保留成功证据。输出包含采集内容、证据、统计、问题列表和完整性，必要证据不足则进入信息收集。

不再存在画布分组入口。旧发布/运行快照继续保留原定义，升级后的流程使用新的实际节点。

### AI分析：Agent 或大模型

“AI故障分析”选择平台已发布Agent或模型、固定版本和分析任务。选择Agent不重复配置它内部的模型、知识与工具。FBB分析仅负责诊断，不能直接批准或执行设备处置。

同一个节点可执行多轮：首次读取基础告警与实际拓扑；如果证据充分直接进入故障处理，如果有可查询缺口则进入补充诊断采证，再带新证据回到同一节点；无法自动确认、存在关键矛盾或达到补证上限则转人工复核。

“证据充分”必须结合场景要求、实际证据引用、身份及版本、时间有效性、必需指标和来源冲突判断，不只看AI可信度，也不能用模拟选项强行放行。没有告警不等于业务正常。

采集和分析引用当前流程的同一份“诊断规则”，FBB以14类场景为初始模板，不建立独立配置中心。补证只针对当前候选相关的能力，不遍历全部规则。当前原型会重新采集本轮需求，保留前轮回执；正式执行器可在核对时间、目标、版本与来源后复用仍有效的证据。执行记录区分每轮AI调用和采集阶段。

Agent和模型共用可查看的请求快照，包含任务、告警、证据、拓扑上下文及输出Schema。输出不合法、资源不可用或超时时保留错误证据并进入明确处理路径，不静默换模型。正式开发需通过适配器对接Agent Management和Model Center的真实发布资源、授权及间接调用依赖检查。

这不省略后续处置检查：诊断形成结论后，仍按动作风险、来源能力、白名单和当前计划决定预授权、审批或人工处理，最终仍需独立验证恢复。

### 缩放、更多菜单与单节点测试

更多按钮使用固定宽度的省略号。菜单从变换后的画布中移出，以屏幕坐标定位，靠近边界会收回可视区域；保留重命名、复制和删除。

画布可以选择缩放比例、放大/缩小、适应画布、定位选中节点；缩放围绕画布中心，适应画布可能缩到12%以看整体，阅读具体节点时从组件进入配置，或使用定位选中恢复可读比例。节点详情独立滚动。

测试窗口默认打开“输入准备”，显示可编辑JSON及参数来源。开始节点示例包含来源系统、设备编号、可选序列号和原始事件；缺少必填字段会失败。诊断节点先生成模拟上游采集结果，再测试当前节点；成功或失败后切换到结果页，可返回修改输入。

单节点测试没有跳过执行授权：写动作及审批仍应在完整流程测试；模拟调用结果不代表已连接真实设备、外部系统或大模型。

### 数据归一

通用“数据归一”组件仍可单独使用；FBB的采集节点在内部复用相同规则，转换设备、PRTG、EMS等不同原始格式。配置是JSON，可修改数组路径、字段路径、告警编码映射、级别映射、数据新鲜度与去重时间窗口。

每条标准告警至少包含：证据编号、来源系统/来源实例、查询任务、原始告警编号、目标实例、标准编码、级别、状态、发生时间、原始报文。相同来源的重复告警保留重复报文；跨来源是否属于同一故障由后续关联分析处理。

字段缺失、目标超出本次监测范围、未知实例、过期时间或来源失败，会输出明确缺口，不能填成“没有告警”。

### 信息收集与重试

通用信息收集组件承接身份歧义、来源缺失、格式问题、诊断复核、故障组选择和人工处理。当前运行令牌、处理人、有效期及处理记录绑定同一次运行。

备注用于记录依据，不会替代缺失的接口事实。身份歧义只能选择接口返回的候选；型号/版本未适配需先完成相应定义与发布，再按版本升级规则重新验证。重查仍失败时继续保留缺口，不自动放行。

并行采集保留成功结果及单项失败，支持明确重试。重试属于组件的受控行为；画布仅表达配置明确、次数受限的重新查询关系，不允许任意无限循环。

## 诊断规则：配置什么、数据从哪里来

“诊断规则”维护疑似故障需要哪些证据、什么条件表示健康，以及确认后向下游输出什么建议。它是流程配置；“诊断依据”展示某次运行实际取得的证据和结论，两者用途不同。

FBB预置的14类规则来自此前确认的故障场景模板，不是系统自动从设备或Agent推断出的事实。规则保存到当前工作流定义，发布后随流程版本固定。运行按启动时的规则快照执行，不能用后续草稿覆盖在途判断。

### 入口与适用范围

AI分析节点和按需诊断采证节点打开同一份流程级配置；FBB工具栏提供快捷入口。其他含AI分析的流程也能显式启用规则。简单查询、通知等流程不强制增加诊断配置。

可新增、复制、启用或停用规则。复制后默认停用，待调整后再启用。停用只影响此后发布的新运行；已发布版本和历史运行保留原规则。

配置分为证据需求、判定条件、输出建议、规则测试。规则名称和说明用于解释业务；适用对象与能力使用已有建模中心定义。

### 证据需求与固定能力引用

先选择目标对象，再显式选择已发布版本及其中的只读能力。对象下拉只列当前存在、已发布且对本流程领域可引用的对象；原引用已撤销或不可用时保留原值并标明不可选，不自动换成另一对象。返回字段候选来自该版本的响应契约，不只限于FBB内置的光功率、日志等能力。HTTP地址、认证与接口契约复用对象能力，不在诊断规则重新配置。

每条证据需求可新增或删除；可选择候选目标或实际拓扑中的关联目标，选择对象自身、监测覆盖来源或两者，定义必需性、返回路径和关联范围。默认只展开第一条，其他折叠，保留用户展开状态；新建需求自动展开。关联关系仍必须由外部实际拓扑提供。

“查看固定契约”展示当前规则选择的同一版本。固定版本不存在、能力缺失或不是只读能力时显示错误，不能回退到最新版。同一流程其他节点引用同一对象不同版本时，检查提示显式统一；规则引用也纳入流程发布快照。

旧契约只声明动态Object而未定义子字段时，可维护子路径，但标明运行时核对。缺失字段、类型不合规或来源冲突进入补证/人工处理，不能视作健康。

### 判定与输出建议

判定条件描述健康范围；不满足时记录异常，数据缺失时保持待补证。输出建议包括根因说明、责任归属、责任团队、建议动作、优先级、SLA和客户侧工单方式。

FBB采集与AI分析使用同一套规则。AI输出保留规则集编号、规则编号和固定流程版本；工单与处置步骤记录实际消费了哪条规则及其业务字段。诊断建议不会替代预检、白名单、身份权限或人工审批。

### 规则测试与模拟值

规则测试接收按证据需求编号组织的模拟响应JSON。先显示健康、异常或需要补证的可读摘要及逐条件结果表，再折叠展示完整JSON与引用证据。可以生成输入结构后自行编辑；空判定、字段类型错误、缺失或冲突都会明确提示。测试不会请求真实接口、创建工单或下发动作。

检查健康、缺少证据或规则停用时，本次结果的建议动作为空，工单类型为none，不建议重启或创建网络故障TT。规则中预配置的动作仍独立保留为配置参考；只有证据完整且判定异常时，才输出本次处置建议，交给后续策略、预检和审批处理。

正常/异常样例值已从业务判定配置移到既有“测试数据”窗口的“诊断响应样例”，与业务阈值分别保存。运行使用独立测试快照，不用后来修改的样例覆盖已有运行。

非FBB流程已支持启用、编辑和独立规则测试，BigData指标能力也可作为证据。通用生产执行器仍需将规则结果与各领域的AI、条件及工单节点契约接通；不能因此宣称每个历史工作流都已自动拥有FBB动态采证。

### 开发数据约定

诊断规则随工作流版本保存；证据需求固定对象和能力版本、目标选择、返回路径、必需性与查询范围；测试样例单独保存；运行证据保留实际来源、实例、请求、能力实现、时间与规则消费记录。

原型以 `diagnosticRules55` 为单一编辑来源，旧FBB执行器读取兼容投影。正式开发应收敛为统一流程定义和规则执行接口，不复制出第二套业务配置中心。

## FBB应用场景

### 外部输入

开始输入示例：

```json
{
  "source_system": "OSS-EMS",
  "device_id": "NEW-ONU-9001",
  "event": {"key": "ALM-20261023-001", "code": "device_down"}
}
```

`device_id`是实际实例标识，不是型号编号；它需要来源命名空间。可附序列号辅助核对。仅知道EG8145V5不能判断操作哪一台产品。

试运行中的“故障场景、验证条件、响应样例”仅控制模拟接口；正式服务输入不接受这些测试开关。

### 从外部事件到业务处理

| 画布节点或业务步骤 | 输入来自哪里 | 处理与结果 |
| --- | --- | --- |
| 开始 | 外部告警或投诉事件 | 接收来源系统、实际设备编号、可选序列号和原始报文 |
| 设备身份与型号查询 | 开始参数 | 调用资源身份能力，定位唯一实际资源、类型、型号、版本与管理入口 |
| 关联资源拓扑查询 | 已确认的实际资源编号、来源系统及查询范围 | 在同一对象能力节点查询并校验连接、组成、监测覆盖和业务关联，按可用/缺口/异常分流 |
| 告警登记、去重及父故障关联 | 原始事件和业务上下文 | 保留入口事件的独立业务语义，避免重复启动/重复TT |
| 多源告警采集 | 实际资源、关系及查询要求 | 动态生成并行目标，匹配能力，查询、汇总、归一及校验；缺口保留来源记录 |
| AI故障分析 | 基础告警、拓扑及已有诊断证据 | 判断结论是否有充分证据；继续、补证或人工复核三种结果 |
| 补充诊断采证 | AI指出的缺口及场景要求 | 调用当前候选所需的只读证据能力，取得新证据后回AI分析；次数受限 |
| 人工复核 | 当前诊断与完整问题列表 | 补证或有依据地修正结论，保留原结论与修订记录，再校验 |
| 独立故障任务确认 | 多个独立故障组 | 用户确认后创建各组处置任务，父任务汇总，不丢弃未完成组 |
| 工单、预检、审批与处置 | 经确认的故障与目标 | 按网络/客户侧/监测例外规则创建或关联TT，执行权限判断及人工审批 |
| 原设备操作结果核对（按需） | 已发出但未确认回执的原请求 | 读取原请求状态或转人工核对，不重复下发；确认受理后再验证业务恢复 |
| 独立恢复与归档 | 新查询的恢复事实 | 核对告警、状态和服务指标，成功关闭对应工单，否则升级或保留待办 |

主流程不固定两轮AI分析，也不强制执行补充诊断采证。基础证据已充分时可一次形成结论。

### 两个资源查询能力

示例接口路径是开发契约建议，不代表客户现网已经提供同名接口。开发时可由适配服务将现有OSS/EMS接口转换为该公共格式。

`GET /api/resources/identity`接收`source_system`、`device_id`、可选`serial_number`。返回唯一`resource`或候选，至少包含实际资源编号、类型、型号、软硬件/接口版本与管理入口，并保留来源、时间、完整性及问题列表。外部编号与统一资源编号可以不同；后续拓扑必须引用解析后的编号。

`GET /api/resources/topology`接收`source_system`、`resource_id`、`direction`、`max_hops`、`include_monitoring`。方向支持双向/上游/下游，默认双向12跳并包括监测系统。返回作用范围内的资源和实际关系，关系分别标记物理连接或监测覆盖。身份查询与拓扑查询返回的根设备类型、型号、版本及管理入口不一致时暂停。

本地测试暂时共用一份可编辑资源样例，两个API分别解析并记录调用；这不表示现网已有两个接口。

实际设备可以跨厂商、型号与版本，且不需要预先在对象建模录入编号。板卡、端口、分光器、光路等继续沿用统一对象结构；没有告警能力的组成对象留在拓扑，记录跳过原因，不强行调用。

### 动态多源采集如何执行

目标来自外部拓扑响应，不要求建模中心预登记每台设备编号。设备与监测系统可一起提供证据，但必须区分设备实际连接、监测覆盖和告警归属。

组件内部按允许类型、公共能力、已发布实现、请求映射和数量上限形成任务。设备通常查询自身；监测系统的查询范围来自实际覆盖关系。没有告警能力的板卡、端口、光路或组成资源可以保留在拓扑，不因此强行调用。

多来源可以并行调用，默认示例限制并发数，超时和重试有上限。每项任务保留唯一标识及来源回执；按任务标识汇总，不能把其他设备或另一轮查询的响应错用为本次成功结果。

缺少型号定义、版本不支持、身份歧义或真实关系缺口时明确暂停或转人工。仅填写备注不会补造缺失的接口事实。必需证据不足不视为采集完成；辅助来源失败可按明确配置保留问题并继续，不能由AI自行宣布两个来源等价。

### 按需补证与多轮分析

例如只有一条LOS告警时，通常还需要上下游状态、光功率或OTDR结果来区分光纤故障、端口问题和终端异常。AI提出候选及所缺证据，采集节点只查询这些需求，然后再次分析。

相反，首轮采集已经取得并校验关键指标时，可以直接形成结论。充分证据示例在首轮采集内部追加只读诊断能力调用；同样需要通过证据检查，不通过高可信度标记强行跳过。

补证次数受限；连续得不到有效新证据时转人工。多个候选可以共存，多个独立故障不能强行合并为一个根因。每轮都有独立来源、时间、AI输入输出及结论记录。

### 多个独立故障的处置任务

分析得到多个独立故障时，用户端展示故障清单、目标、证据和建议处理方式。用户确认后为各组创建关联处置任务，保留父运行与故障组标识；重复点击或使用旧通知不能重复创建。

各组使用本次固定定义与证据快照，并独立检查目标、审批、工单及恢复。父任务聚合进度；某组完成不能把其余组标为已恢复。工单按真实故障范围及去重规则创建或关联，不按告警条数机械建单。

用户可从父任务打开具体故障任务；每个任务仍使用“我的任务”中的统一办理表单。草稿测试产生的子任务留在测试范围，不混入普通用户业务待办。

### 人工复核与修订

有权限的工程师可引用本次已校验证据，并修改根因说明、故障场景和相应建议动作。实际目标固定为本故障任务的已核验资源，不在复核表单中切换设备；动作来自所选场景的配置，仍由适用能力和允许范围检查。修订必须写明依据，保留AI原结论、变更内容、处理人和时间。工程记录编号或证据链接用于追溯，不能直接替代可信接口返回的指标。

修订使旧处置计划和授权失效，后续重新执行预检与审批。人工备注不能替代型号适配、身份定位、白名单或独立恢复事实；这些缺口仍需修复来源或配置。

### FBB预置的14类诊断场景

| 场景 | 主要检查对象/证据 | 后续处理重点 |
| --- | --- | --- |
| 网络设备不可达 | OLT等设备可达性、状态与来源告警 | 电源/设备根因复核，重启受审批 |
| 光纤中断 | 光路LOS、OTDR、光功率 | 派现场施工，独立复测 |
| 端口问题 | 端口状态、错误、管理状态 | 按所属设备匹配端口实现 |
| CPE配置问题 | 终端在线、配置与认证信息 | 按责任归属处理 |
| 骨干配置问题 | 路由、BGP与配置检查 | 网络配置处置受控 |
| 客户LAN问题 | LAN连通、客户设备/现场证据 | 不建网络故障TT |
| 客户侧市电问题 | 供电监测、现场确认 | 客户侧转交或信息类TT |
| 国际网关问题 | 出口、全局告警、路由与探测 | 出口路由操作受控 |
| 网元配置问题 | 配置差异、日志与业务模板 | 明确对象、版本和影响范围 |
| 报文/信号丢失 | LOS与丢包等不同指标 | 分别保存指标，不能混用阈值 |
| 低光功率 | Rx/Tx、阈值与光路 | 光路修复与复测 |
| 速率问题 | 速率、利用率、业务配置 | 支持严格白名单的单服务动作 |
| 高时延 | RTT、抖动、路由与拥塞 | 业务影响及网络操作审批 |
| CPE调制解调器问题 | 在线、硬件/固件、日志 | 客户侧处理或设备更换施工 |

这些是可配置的诊断方案，不是14个不透明业务阶段节点。采集内容放在“证据需求”，阈值放在“判定条件”，动作、责任团队、优先级、SLA及客户侧TT方式放在“输出建议”。规则可以新增、复制或停用，不再把14项当成不可扩展的固定清单。

### 证据需求的运行含义

选择规则中的对象、固定版本、只读能力和返回字段后，运行器根据本轮候选以及外部实际拓扑生成任务。一个规则可以需要多个能力，同一个采证任务也可以同时服务多个候选。缺少必需证据时暂停或补证，辅助缺口保留警示。

例如“光纤中断”可以引用光路的光功率和OTDR能力，再依据实际连接获取相关ONU的辅助指标。规则描述需要什么证据；任务记录实际调用了哪个来源、哪个实例及哪个适用实现，不用对象类型层级推导物理连接。

### 诊断能力与任务契约

本轮增加的17项只读能力：可达性、网元状态、运行日志、光路信号、光功率、OTDR、端口状态、接口统计、配置检查、认证/DHCP、路由/BGP、连通性、供电、现场核实记录、出口网关、路径性能、硬件状态。它们保存在原有对象的功能列表，不增加新的对象根结构。告警系统提供相应监测查询实现，设备及资源只定义适用能力。

公共输入示例：

```json
{
  "instance_id": "MON-EMS-01",
  "target_instance": "FIBER-021",
  "service_id": "FBB-AA-021",
  "window_minutes": 10
}
```

`instance_id`是能力来源实例；`target_instance`是实际被诊断对象。监测系统查询光路时二者不同；设备自查时可以相同。请求中的目标必须属于本次拓扑和真实监测范围。

公共返回示例：

```json
{
  "success": true,
  "object_id": "alarm_system",
  "target_instance": "FIBER-021",
  "capability": "query_optical_power",
  "metrics": {"rx_power": -29.5, "tx_power": 2.1},
  "observed_at": "2026-10-24T01:00:00Z",
  "raw_payload": {"source": "EMS", "record_id": "SAMPLE-001"}
}
```

这些路径与响应是适配契约示例，非客户现网接口。具体型号实现沿用既有适用软硬件版本、管理入口、执行模板及Schema。本轮模型与能力快照为1.3.0，流程固定发布依赖；不静默升级旧运行。

任务按“来源实例＋目标实例＋能力＋时间窗口”去重，同时保留引用它的场景需求和候选。每项固定实现编号、实现版本、管理入口及请求参数。默认最多8个候选、96项诊断任务；超限显式暂停，不静默截断。并发、超时、重试、能力允许列表可在节点配置。

汇总必须与本次计划和原始调用回执一致。必需来源失败、指标缺失或类型不符、证据超出时效（默认300秒）、同目标同指标多来源矛盾均阻断最终诊断和写操作；辅助需求缺失产生警告。当前原型对同名指标采取严格一致检查；正式适配应先统一单位、时间窗口和语义，连续指标可增加容差与来源优先规则。

### 测试与运行查看

新节点提供一次明确的“生成上游测试输入”，实际在模拟器中执行所需上游链路后提供可编辑JSON，再单测当前节点。不得把手工修改的输出当成原始证据。

运行详情增加“场景诊断采证”标签：先看候选数、任务数、能力种类和峰值并发，再看来源、目标、能力及版本、逐项状态；完整任务和原始响应折叠查看。试运行增加来源超时、必需指标缺失、证据过期、多来源冲突条件。

暂停后的“重新查询固定配置来源”仍以事实为准；“模拟来源恢复并重新采证”是显式改变测试条件并再次调用模拟来源，不是生产功能，也不是输入备注后跳过检查。源响应逐项覆盖目前可在模拟运行器测试中配置，尚无单独的第二轮响应JSON编辑UI。

### TT、处置与恢复

告警登记去重；已存在父故障时关联证据，避免重复建网络TT。确认网络故障后创建或关联TT，保存根因、证据、优先级、SLA、归属与建议动作。

客户LAN、电源、CPE等客户侧问题不建网络故障TT，可配置建信息类TT或直接转交。未确认故障保留监测例外记录；证据缺失不能作为“未确认故障”的正常分支放过。

A分支仅允许来源与型号实现均支持、满足最新领域约束、目标白名单、前置检查及单服务影响范围的预授权动作。B分支人工审批固定本次目标、参数、功能版本和实现模板。C分支禁止自动下发，转授权团队处理。

现场施工建立关联施工记录；完工后仍需独立验证。处置成功回执不能代替持续业务恢复。恢复来源不可用、时间窗口不足、告警未清除或指标未恢复时保持未解决/升级；子故障流程不能擅自关闭父TT。

### 人工审批、多结果与重定向

审批针对一个固定处置计划：目标实例、动作、请求参数、能力实现版本及诊断依据。进入待办后先核对计划，填写处理说明，再选择结果。

| 操作 | 状态与去向 | 必须保持的边界 |
| --- | --- | --- |
| 批准本次计划 | 走“批准”出口，执行受控对象能力 | 提交时核对计划与依据、处理人、有效期；执行时仍检查领域约束、白名单和前置条件 |
| 拒绝并转人工 | 走“拒绝”出口，FBB默认到人工处置 | 记录拒绝原因，沿用当前TT；不执行设备动作、不当作故障已解决、不重复建网络TT |
| 退回补充 | 跳转到配置允许的上游补充/查询位置 | 限定身份查询、告警任务、诊断采证或前置检查；不能直接跳到指令下发/关闭节点。重新检查和再次审批 |
| 挂起 | 保留待办，运行状态为“已挂起” | 不消耗为普通继续出口；记录原因、提醒和截止时间，替换待办令牌；挂起中不能批准 |
| 恢复并重新校验 | 重新执行检查，之后产生新审批 | 计划与依据仍有效时重新预检；变化或过期时重新查询外部身份、拓扑和证据；不能沿用旧批准 |
| 超时升级 | 独立“超时”出口，FBB默认通知负责人后转人工 | 未到截止不能执行超时升级；超时不等于拒绝、不自动批准、不自动关闭TT |

节点配置中的“下一步”及审批配置都编辑同一组结果连线。退回目标作为受限重定向配置存储，不靠画任意回边绕过发布时的环路检查；运行历史记录实际返回位置和每轮处理。

默认审批30分钟、挂起60分钟、15分钟提醒、依据有效10分钟；最多退回2次、恢复3次。默认退回诊断采证，恢复先预检；过期恢复须从外部身份解析重新开始。次数和时限在审批配置中调整，恢复位置在折叠区查看。上限防止无限退回/挂起。

重定向会清理受影响节点的当前输出、当前诊断结果和授权，历史步骤与回执保留；再登记同一运行的事件时沿用原事件，不误判成另一次触发。TT按原幂等关联保持，确需现场作业时由已有人工/施工链路生成关联施工单。完工仍必须经过独立恢复查询。

运行中心“待处理”包含挂起，也可单独筛选“已挂起”。刷新页面后挂起待办、原因和固定运行快照保留。本地原型显示提醒/截止时间，提供到期处理按钮与仅草稿测试可见的“模拟超时”；真实定时提醒、后台自动超时升级和跨进程恢复必须由服务端调度实现。业务模式按节点处理人配置分配待办，原型使用演示成员；草稿测试保留测试身份。正式开发应接入组织、角色与值班表，并在服务端实施授权。

## 异常接手与原操作核对

这些交互在客户端“我的任务”办理，运行中心查看同一运行和证据。它们复用已有节点，不需要再画一组状态查询节点。

### AI分析失败：转交后有人继续处理

触发条件：Agent/模型不可用、超时或返回不合规。界面提供“重试分析 / 转人工接手 / 结束本次任务”。技术失败与证据不足分开，后者仍走补证或人工诊断复核。

“转人工接手”真正进入配置的人工节点，生成新的本地待办、处理人和通知，保留原失败节点、已有采集证据、运行版本、工单关联及交接说明。身份或拓扑缺口也可通过同样方式接手。

没有有效诊断时，人工待办提供“修复后重新诊断”或“结束自动诊断并保留人工记录”。前者回到原查询/分析位置，重新取得事实后仍需预检与审批；最多2次，防止反复无效重试。后者保留人工跟踪记录，结果明确为未确认恢复，不自动关闭故障单。填写一段备注不能直接越过诊断进入恢复验证。

原型在明确点击修复并重新诊断时清除本条任务的模拟AI异常。正式后台必须检查真实配置、提供者状态和权限，不能用清除标志代替修复。

### 设备回执未知：查询原请求

触发条件：写入请求已经提交，但超时、连接中断或其他原因使调用方无法确认设备是否执行。若请求尚未发送或执行前校验失败，走原技术失败路径，不能伪造“已发送”。

设备操作提交前保存原请求编号、幂等键、实际目标、固定对象能力/实现版本、参数及时间。核对、重复点击或刷新只能查这次原请求，不能重新生成指令。

待办显示原请求、目标、能力版本、当前状态与核对历史。存在已发布只读查询能力时，提供“查询原请求状态 / 转人工核对”；来源没有查询能力时，仅提供人工核对。

| 核对结果 | 用户看到的状态 | 后续处理 |
| --- | --- | --- |
| `accepted` | 原执行系统确认已受理并提供回执 | 进入独立恢复查询；已受理不代表已恢复 |
| `processing` | 原系统仍在处理 | 保留当前待办，之后继续核对 |
| `failed` | 原系统明确失败 | 转人工修复，保留原TT，不重复发原指令 |
| `unknown` | 当前仍无法确认结果 | 保留待核对，可再次查询或转人工 |
| 查询失败 / 目标或原请求不一致 | 核对未完成，显示原因 | 保持未知，不能将其当成成功或无操作 |

查询期间防止重复办理；完成后更新待办令牌。刷新保留原操作和核对历史，释放中断的查询状态，不触发写操作重放。

### 人工核对需要什么

人工待办要求填写核对结论、外部系统回执或工程核对记录编号、处理说明。只有权限和备注不够，还要有可追溯依据。

结论为未知时继续等待；确认已受理后进入独立恢复查询；确认失败后转人工修复。工单/施工单的处理、告警清除、业务指标和观察窗口仍按原规则检查，不因人工核对而绕过。

### 给开发的最小数据约定

资源拓扑服务对象仍用标准功能结构，新能力为 `query_operation_status`，示例路径 `GET /api/operations/status`。这是适配契约示例，正式开发对接现有执行系统，不表示客户已有此URL。

| 字段或记录 | 含义 |
| --- | --- |
| 请求 `request_id` | 原执行请求编号，必填 |
| 请求 `idempotency_key` | 原幂等键，必填，核对过程中保持不变 |
| 请求 `instance_id` | 原操作实际目标，必填 |
| 请求 `source_system` | 原管理入口/来源命名空间，取原操作记录 |
| 返回 `request_id / idempotency_key / target` | 必须与原操作一致，否则不能采用 |
| 返回 `status / receipt_id / message / observed_at` | 状态、外部回执、说明、观察时间；状态限定上述4种 |
| 返回 `success` | 只表示本次状态查询成功，不表示设备操作完成或业务恢复 |
| 人工记录 `status / reference / note` | 结论、外部依据编号、说明，关联原请求与处理人 |
| 交接记录 | 来源失败节点、重试目标、已有证据、处理人、待办、关联TT及时间 |

原型待办类型分别为 `ai_failure48`（AI失败）、`manual_handoff54`（无有效诊断的人工接手）、`operation_check54`（原请求待核对）、`manual_operation54`（人工核对）。这些后缀是原型实现标记，正式接口应使用稳定的业务类型名称。

前端只展示服务端判定的计划、状态和可用操作。正式后台负责请求提交与账本原子记录、幂等、可靠回执/查询、任务领取与令牌校验、权限、超时调度及审计；浏览器缓存不能承担这些职责。

## 知识图谱

### 对象建模与图谱如何往返

从类型、型号/规格的“图谱聚焦”进入知识图谱时，顶部显示当前聚焦对象和来自哪个对象。默认浏览和聚焦只改变视图；只有明确新增或编辑关系并保存，才写入起点对象草稿。

| 操作 | 行为 |
| --- | --- |
| 点击图谱节点 | 只改变选中项和右侧详情，不自动改变聚焦根节点 |
| 以此聚焦 / 搜索定位 | 更换聚焦根节点，并保留上一视图 |
| 查看全局关系 | 切换为全局视角，仍保留对象建模入口的来源 |
| 上一步 | 返回上一聚焦/视图，恢复根节点、选中项、配置版本及画布位置；最多保留12步 |
| 打开配置 | 打开统一对象详情或规格详情，提供“返回知识图谱”；明确编辑后才进入草稿编辑 |
| 返回知识图谱 | 恢复打开配置前的图谱和选中项，避免重新搜索 |
| 返回对象建模 | 恢复进入图谱前的类型、对象/规格详情页签、查看状态、搜索、分类、字段筛选、页码及列表滚动位置 |
| 点击左侧菜单 | 视为主动进入模块，清除当前临时往返上下文 |

正在编辑类型且有未保存内容时，返回前保留“继续编辑 / 放弃修改并离开 / 保存草稿并离开”。“模型关系”处于选中状态时再次点击不再意外跳回全局视图。

这是当前页面内的导航上下文，刷新页面不保留这条临时返回链，也没有模拟浏览器历史按钮。正式接入后台建议由统一路由保存页面和查询参数，进一步支持可复制的深链接及浏览器前进/后退。


### 模型关系

保留全局对象关系。全局/聚焦切换放在图表区域，搜索定位不隐藏其他全局对象。可选编辑中配置或已发布配置，查看关系名称、跨领域关系及对象详情。

对象聚焦从类型展开厂商、型号/规格，也可展示定义的组成、连接、业务与事件关联。厂商分组是产品目录维度，不表示设备处于网络上下游。

### 在图谱中新增关系

“模型关系”提供“新增关系”和“关系编辑”入口。常规方式是点击新增，使用名称或编码模糊搜索起点、终点；当前选中对象会自动作为起点。无需熟悉拖线即可完成。

也可以打开关系编辑模式，从对象类型的连接点拖到目标，或依次点击起点、终点连接点；键盘Enter和空格可触发同一入口。连线先确认，再进入已有关系编辑器，不立即写入。取消拖线或退出编辑模式不会留下草稿关系。

后续直接使用对象建模的关系定义、来源与映射、关联测试页面。保存写入起点对象的关系草稿，图谱和对象建模读取同一份数据；发布快照保持不变。检查内容包括起点维护权限、跨领域共享、重复定义、只读来源及参数契约。

普通业务关系允许形成环，不能套用类型继承树的禁止循环规则。同类对象之间的关系需要明确允许不同实例关联。继承或规格归属等派生连线不通过业务关系编辑改接。

已发布图谱只能查看冻结关系；新增前需明确切换到编辑中模型。实例探索不提供编辑实际连接的入口，外部事实仍由来源系统维护。

### 实例探索

输入来源系统和设备编号，按需查询实际拓扑。来源、版本、编号与真实连接来自外部接口模拟响应，右侧只读显示事实和来源，不提供“登记实例”。

默认显示实际连接及选中资源的监测覆盖；可展开全部覆盖，避免两套监测系统连向所有资源时遮挡画布。布局仅影响展示位置，不推导连接。

资源场景也可切换为BigData指标或TeleConnect会议，读取各自外部响应并展示业务字段；不会要求它们填写设备固件。当前查询证据和历史查询默认在实例探索原地查看。

从运行详情进入时展示该次资源快照，可返回运行记录。新的查询会产生新的查询证据，不覆盖旧运行快照。模型定义、外部测试响应、查询事实和运行证据不混成同一套可编辑台账。

### 查询记录与证据如何查看

“本次查询证据”原地打开只读详情，展示输入与来源、资源与关系、拓扑快照和原始响应。没有完整性判定的历史记录显示未判定，不能据此推断无告警或已恢复。

“历史查询”默认限定当前资源和来源系统，可搜索查询编号或时间；打开一条记录仍在原地。只有“查看全部查询记录”进入运行中心，并保留返回实例探索的入口。

运行中心的“查看快照”打开同一份原地详情。关闭只关闭弹窗，不再跳回实例探索，不丢失列表筛选和滚动位置。拓扑快照只读，可扩大查看，不允许编辑历史关系。

“以此为起点探索”才切换到实例探索，并保留“历史快照”及原查询时间。“重新查询 · 新记录”才按原始输入执行新的模拟请求，生成独立查询编号并关联原记录；旧快照保持不变。新查询同时保存来源、输入、查询时间与查询人，解析后的身份和原始传入编号分别保留。

查询使用稳定编号，不以列表下标识别；排序改变不影响打开目标。历史缺失的查询人显示“历史未记录”，输入缺失时仅从该记录保存的响应身份回显，不借用当前页面后来填写的值。正式系统应由服务端分配查询编号并保存不可变快照及权限。

## Agent Management与流程服务

配置继续沿用平台Configuration/Release结构，应用中选择Digital Employees、Skill和可调用流程；Release控制可见成员/部门、API及TeleConnect发布入口。MCP/Skill/Agent资源不再复制成另一套资源管理。

流程本身维护描述、适用条件、排除范围、示例问法、关键词、输入输出和执行影响。Agent使用这些信息命中流程，收集外部设备信息后确认。当前OSS示例应用已固定本轮FBB流程版本；BigData和TeleConnect也保留统一能力示例。

流程服务契约为异步启动、查询状态与待办续办；启动携带幂等键。相同键与相同输入复用运行；不能用相同键更换设备。未知或额外输入、缺少必需字段不能直接运行。

HTML中服务调用为同一运行器的本地模拟；界面给出HTTP契约，不表示已部署服务。真实API需在平台服务端实现身份认证、授权、状态持久化及幂等事务。

## 对象、流程、Agent的引用影响

三个入口共用一套引用扫描逻辑：类型或型号的“引用影响”、流程的“引用检查”、Agent Configuration的“引用检查与依赖链”。

对象视角列出模型关系终点、关系解析能力、型号实现、显式继承、流程节点，以及通过已发布流程间接引用的Agent。流程视角列出节点直接能力调用或动态允许范围，也显示应用所固定的流程版本。Agent视角区分待发布的选择与已发布的固定版本，继续展开到该版本的对象能力。

列表按引用方分组折叠，可搜索流程、节点、能力或版本，筛选草稿/发布引用。“引用有效”只表示目标及契约能够解析，不等于当前实际设备具有可执行实现。

动态调用还要检查实际类型、型号、软硬件版本、管理方式和已发布实现。允许范围中某类型不提供当前能力时显示“不适用 · 缺少能力，禁止派发”；不会借上级名称自动调用。规格影响是运行时可能匹配到该规格的间接影响，不能误认为流程已经绑定某个实际设备。

新草稿不会更改旧发布快照。Agent已发布流程版本缺失时不退回最新版。当前引用检查读取编辑中的流程和Agent选择，避免只检查上一次保存内容。

引用影响中提供显式升级评估，可选择草稿节点并查看适配问题；不自动替用户修复失效字段，也不自动发布流程或Agent。正式后台应将同样的依赖校验纳入发布事务，历史运行继续使用自己的快照。

## 运行中心与知识案例

运行列表是主体，信息说明折叠或整合到工具栏。业务运行进入运行详情；查询记录的“查看快照”原地打开只读查询证据，不把两种记录强行放进同一套办理界面。

FBB详情分为诊断概览、执行过程、采集与归一证据、场景诊断采证、结果与恢复；可继续打开查询与结果校验、审批历史及原操作核对记录。概览显示外部设备、任务数、实际峰值并发、告警数与故障组；完整报文放在可展开区域。

每个步骤可查输入、输出与失败原因。来源证据可追溯到型号实现及原始报文。待办只对授权处理人开放，使用当前令牌；过期或修改后的执行计划不能复用旧批准。

运行完成后可整理知识案例草稿，经复核和审核后发布。诊断建议、已执行动作、独立验证与最终结论要分别保存。无恢复查询的监测例外不能写成“业务已恢复”。

## 测试数据入口

“演示工具”中有“测试数据 · 外部响应”，FBB试运行和实例探索也能进入。可编辑拓扑JSON、按来源覆盖原始告警响应，导出测试数据；BigData/TeleConnect外部响应有明确入口。当前流程使用诊断规则时，测试数据内提供“诊断响应样例”，集中编辑健康/异常模拟值；业务判定阈值仍在诊断规则中。

默认模拟器会将根设备编号替换为本次外部输入，使未在任何模型台账中出现的新编号也能测试。真实关联仍取自响应JSON，不由编号或类型树生成。这是测试适配器的参数化，不是生产资源解析算法。

真实环境中，身份与拓扑由OSS/EMS/资源来源返回；指标实例来自数据平台，会议实例来自会议系统。缓存、标识映射与来源同步属于运行/集成层，复用现有资源系统。

测试数据修改不改变模型发布版本；改变模型草稿也不能修复一个仍使用旧发布快照的运行。需要按依赖升级并重新发起验证。

## 后续建议

- 后端统一依赖索引与发布事务：将原型的引用检查接入服务端；在删除、停用、升级时展示影响与回归要求。
- 契约差异服务化：当前已有可读差异和显式升级交互，正式后台需要统一差异算法，并补足深层Schema兼容性及行为兼容性评估。
- 统一运行接口：原型保留新旧执行器兼容路径；正式开发须统一组件契约与调度接口。不能仅给新流程添加版本标记，就认为所有旧组件已完成运行适配。
- 工程拆分：按定义、版本、引用、能力匹配、运行器、UI和测试适配拆分模块，避免照搬单文件累积覆盖函数。
- 大规模加载与路由：树/图谱服务端搜索及按需加载，统一深链接、离开提示和权限变化处理。
- 真实FBB纵向接入：优先打通外部身份/拓扑、一个只读多源采集场景、证据诊断和独立恢复；再开放受控写动作。

| 并行运行器 | 动态数组、并发限流、超时/重试、部分成功、取消、来源配额、断点恢复与持久任务 |
| 告警归一 | 不同系统字段/状态/时间/级别适配、去重窗口、原始报文留存、质量与监测覆盖检查 |
| 证据驱动的AI分析 | Agent/模型统一适配器、固定资源版本、只读工具边界、完整间接循环检测、真实结构化输出、候选可追溯、采证工具计划受约束、跨设备传播及多个故障组、证据引用、提示注入防护、可信度校准与评估集 |
| 影响分析 | 复用业务承载与客户/业务映射API；不能仅凭局部设备拓扑推断全部受影响客户 |
| 多故障处理 | 将确认后分组处置落到持久子任务，事务创建、防重复、各组权限与TT关联、父任务聚合和各组恢复 |
| TT与现场作业 | 对接权威ITSM/施工系统、建单幂等、SLA、派发升级、父故障关联与闭环回写 |
| 客户端任务与通知 | 复用TeleConnect任务/消息能力，运行与待办统一标识、角色可见性、通知去重与已读、实时状态同步、过期操作保护、深链接和服务端提醒 |
| 审批状态机 | 批准/拒绝/退回/挂起/恢复/超时持久化，真实身份分配，原子领取与令牌防重放，服务端定时提醒、超时升级，受影响结果失效及受限重定向 |
| 执行与恢复 | 人工审批身份、不可放宽的策略、白名单、参数快照、防重放、真实指令适配、回滚与独立持续恢复查询 |
| 原请求状态核对 | 提交账本与幂等事务、外部回执/只读状态适配、请求和目标校验、未知/处理中状态、人工有据核对、刷新或断线不重发 |
| 异常转人工 | 真实待办和责任分配、证据与工单交接、无诊断时限制恢复、修复后受控重跑、结束自动诊断后继续人工跟踪 |
| 服务与Agent | 应用发布依赖、发现/推荐、参数补齐、鉴权、服务启动/状态/续办API、并发与幂等事务 |
| 图谱与证据 | 全局定义图、外部查询拓扑、快照存储、来源权限、较大拓扑布局/分层加载与证据检索 |
| 代码与资源执行 | Java/Python/JAR/JavaScript沙箱、包扫描、网络/凭据边界、MCP/Skill/Agent平台执行器与版本管理 |
| 跨领域扩展 | 指标、会议、任务等对象各自的外部解析/能力适配与页面扩展，仍遵循统一契约 |
| 维护与查询审计 | 服务端创建/修改时间及登录身份、历史未知兼容、稳定查询编号、不可变查询快照、重查关联及访问权限 |
| 历史存储 | 服务端保存运行、分步回执与大报文；浏览器只缓存必要视图，分页、留存、归档及容量限制，不能将单文件localStorage当生产存储 |
| 运维保障 | 审计、监控、日志脱敏、权限/租户隔离、告警去重、容灾、测试自动化与安全评审 |

建议先把“一个外部设备编号 → 可信拓扑 → 多源基础告警 → AI分析与按需采证 → 有证据的诊断 → 人工确认 → 必要时核对原操作 → 独立恢复”的真实集成跑通，再逐步开放受控写动作。页面已经提供这些配置与状态的参照，正式开发不应把示例设备表或模拟推理当作后台实现。
